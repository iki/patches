# cf and Cloudflare Config history

Cloudflare Config 0.26.0 → 0.27.0 → 0.28.1 → 0.30.2 did not establish Bun module-hook support. The independently retained validated prebuilt-output interface remains useful.

The account-API/config coupling defect was resolved in published [cf 1.0.0-beta.27](https://github.com/cloudflare/cf/releases/tag/cf%401.0.0-beta.27), which contains [PR #372](https://github.com/cloudflare/cf/pull/372), commit d4a5d173803daca22f69ea8cc441b281078b94f6, closing [issue #207](https://github.com/cloudflare/cf/issues/207). A controlled loopback API test observed one request, explicit account/compliance settings, and no evaluation of a deliberately throwing config. [Verified follow-up](https://github.com/cloudflare/cf/pull/372#issuecomment-6685381465).

The historical [worker activation adapter](https://github.com/iki/cf/commit/6ce83dc92afba5f354002643c4260c6e59bb93b6), based on 6808c0f8449e0dfe9d2c41ef0143485265432ed1, remains reusable evidence. Supported scoped HTTP integration is no longer classified as a bypass of that resolved defect. The Bun config-loading workaround remains independent. These observations were recorded by 2026-11-06; catalog curation changes no remote resources.

On 2026-11-20 the cf 1.0.0-rc.2 release selected Config and Build Output Utils 1.0.0-rc.1. The adapter uses their matching rc.2 packages, published on the beta channel. Their stable tags were 0.32.1 and 0.9.14 respectively. The v1 writer takes an options object with `buildContext` and the config package exposes `resolveAndParseConfig`. The updated helper supports a single precompiled Worker and assets. The mobile profile retains the v0 adapter until its cf version and output reader move together. [CLI package](https://registry.npmjs.org/cf/1.0.0-rc.2) · [Config](https://registry.npmjs.org/@cloudflare%2fconfig/1.0.0-rc.2) · [Build Output Utils](https://registry.npmjs.org/@cloudflare%2fbuild-output-utils/1.0.0-rc.2)

On Windows x64 the native rc.1 and rc.2 loaders rejected object and function configs at explicit paths containing spaces under Bun 1.4.2 and 1.4.5. Under Bun 1.4.2 the adapter wrote v1 output for both config forms. It preserved an existing directory, rejected invalid configuration before creating output and removed a partial write so a corrected input could be retried. The CLI's own rc.1 reader resolved the default Worker's main module. Upward discovery, container builds and deployment are outside this helper's coverage. The signed versioned fork at `c8da7f85f82ba18dbd02e7037eb7e5dc6b2bcc95` is based on the release commit `87e509e317dcd36dbe7e4b7e095dda628b91285c`. [Versioned source and reproduction](https://github.com/iki/cf/blob/c8da7f85f82ba18dbd02e7037eb7e5dc6b2bcc95/downstream/BUN-PREBUILT.md)

The [upstream availability update](https://github.com/cloudflare/cf/issues/252#issuecomment-7037363043) links the tested rc.2 adapter and its scope.

The refreshed Windows x64 web profile ran the v1 adapter on Bun 1.4.5. Both the direct rc.2 native loader and the CLI-resolved rc.1 native loader rejected object and function configs at explicit paths containing spaces. The adapter wrote validated v1 output for both config forms, preserved existing output, rejected invalid configuration and supported retry after a failed write. The CLI's own reader resolved the default Worker's main module. The mobile profile also passed its v0 helper with cf 1.0.0-beta.27, Config 0.30.2 and Build Output Utils 0.9.10 on Bun 1.4.2. ## 2026-11-28

The 1.0.0-rc.6 CLI resolves Config and Build Output Utils at 1.0.0-rc.4. The web profile selects 1.0.0-rc.5 of both directly. On Windows x64 and Bun 1.4.5, both native config loaders rejected object and function configs at explicit paths containing spaces. With the existing v1 helper, both config forms produced validated output readable by the CLI's own rc.4 reader. Invalid configuration left no output, an existing directory was preserved and a missing bundle could be corrected and retried. The helper and test from the rc.2 fork need no code changes for this package group.
