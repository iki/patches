# Bun and Undici history

No dispatcher workaround has been retired. Recorded transitions were Undici 8.12.1/Wrangler 4.151.0 → 8.12.2/4.151.1 → 8.12.3/4.153.0 → 8.12.4/4.158.0. Matching Miniflare pins moved from 5.20261012.1-beta through 5.20261023.0-beta to 5.20261104.0-beta. These package upgrades did not resolve Bun's dispatcher defects; installed-package resolution and global-fetch routing remain separate fixes.

The source observations include loopback rejection of the unpatched shim/global-fetch paths and successful installed Undici dispatch. They are dated evidence, not fresh validation by catalog curation. See the related [Workers SDK history](../workers-sdk/HISTORY.md).

## November 20, 2026

The two prerequisites passed separately with Undici 8.13.0 and Bun 1.4.2 on Windows x64, in both the pristine and patched Wrangler 4.165.0 installations. The resolution test loaded a working installed Pool without changing global fetch. In the dispatcher test the native request reached loopback, and the adapted request consumed the mock expectation. The corresponding Wrangler and Miniflare versions were 4.165.0 and 5.20261118.0-beta. [Wrangler regression](../workers-sdk/HISTORY.md)

robobun closed the installed-first resolution proposal unmerged on November 17 because it conflicted with main. Bun 1.4.5 still maps the bare specifier to its built-in Undici module. The separate built-in dispatcher proposal and the installed-package resolution request remain open. [Closure](https://github.com/oven-sh/bun/pull/36102#issuecomment-6943950827) · [1.4.5 resolver](https://github.com/oven-sh/bun/blob/a7733435cf40429e3b35c36072769df2052b80f1/src/resolve_builtins/HardcodedModule.rs#L300) · [Dispatcher PR](https://github.com/oven-sh/bun/pull/39250) · [Resolution request](https://github.com/oven-sh/bun/issues/17799)

On released Bun 1.4.5 (`a7733435cf40429e3b35c36072769df2052b80f1`) with Undici 8.13.0 on Windows x64, native resolution returned `undici`. The bare Pool lacked `dispatch`, `close` and `destroy`. Loading the installed entry supplied all three methods and its Pool returned HTTP 200 on loopback. Native global fetch reached the loopback server despite receiving a network-disabled MockAgent. The installed fetch consumed the mock responses, all expectations were satisfied, and both resources closed. Both adapters remain active. [Bun release](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.5) · [Pool lifecycle issue](https://github.com/oven-sh/bun/issues/39247) · [Published 1.4.5 results](https://github.com/oven-sh/bun/issues/39247#issuecomment-7037359402)

The refreshed web profile ran each adapter in a fresh Bun 1.4.5 process with Undici 8.13.0 on Windows x64. The installed Pool returned HTTP 200 without replacing global fetch. In the separate routing check, native fetch reached loopback and the adapter consumed the MockAgent expectation. Both checks also passed on Bun 1.4.2 with Undici 8.12.4 in the mobile profile. For the 1.4.5 run, staged copies of the two historical fixtures asserted exactly 1.4.5 in place of 1.4.2. All behavioral assertions and adapter bytes matched catalog commit `47c3847e721696b03500931f94917f12870a005f`. ## 2026-11-28

On Windows x64 with Bun 1.4.5, the frozen web profile selected Undici 8.14.0 alongside Wrangler 4.169.0. The built-in Pool lacked `dispatch`. The installed Pool returned HTTP 200 and closed while preserving the native fetch identity. Native global fetch reached the loopback server despite the network-disabled MockAgent. The scoped adapter consumed the mock reply and exhausted its expectation. The two controls ran in separate Bun processes with the historical fixture's runtime assertion set to exactly 1.4.5. Both existing adapters remain required. [Published Undici](https://registry.npmjs.org/undici/8.14.0) · [Worker integration](../workers-sdk/HISTORY.md#2026-11-28)
