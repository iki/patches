# Patches

This repository contains only dependency-fix catalog material and its reusable
procedures. Organize records by the upstream that owns the defect, then related
packages. Keep consumer names, repository URLs, deployment identifiers, full
application integrations, private setup and conversation transcripts in their
owners. Do not copy them into catalog prose, paths, source records or Git history.
Upstream projects, contributor attribution, fork references and issue/PR links
are required evidence and remain explicit.

Use English and UTF8 LF. Preserve genuine upstream licenses and notices exactly.
Retain copyright holders and distinguish byte-exact upstream copies from curated
catalog material. Do not fabricate an upstream origin, claim byte equivalence
after a transformation, or assign a new license merely because code is public.
Bind maintained artifacts to a real catalog source-snapshot commit. A pending
snapshot placeholder is preparation, never a publishable verification result.

Read the applicable source skill and its linked lifecycle or integration rules.
Use stable independently removable fix IDs, exact package/runtime versions,
prerequisites, source/fork base and head, regression evidence, limitations and
removal criteria. Keep retired fixes and superseded pins in package history.
Every package remains discoverable after its final active fix retires.

Bun 1.4.2 runs this dependency-free host verifier. Aube 2.5.1 owns JavaScript
dependencies and the sole lockfile. Use frozen installation, step:check after a
completed implementation step and review:check before publication. Normal gates
remain offline, bounded and separate from upstream/consumer regressions. Preserve
all negative cases and limits; do not weaken checks to make an update pass.

Independent tasks use registered codex/ branches and worktrees beneath the primary
checkout's .cache/worktrees. Preserve original baselines and unrelated changes.
Record task ownership and actual verification outcomes in private operational
receipts; durable package changes belong in package history. Ordinary publication
uses checked signed task commits and explicit signed linear integration to
https://github.com/iki/patches.git. Recheck destination, signatures and refs, and
reconcile uncertain outcomes before retrying. History rewriting requires explicit
task-specific user authorization; an exceptional cleanup does not change the
ordinary policy or authorize changes to upstream or consumer history.

The user-authorized removal of consumer context supersedes historical instructions
to retain that context publicly. Preserve the complete original evidence backup
outside this public repository. Do not include that private archive or old refs in
the sanitized publication. Package history contains neutral maintenance changes;
mixed-task conversation and operational evidence remain private outside Patches.
Installing these skills never grants authority to send
upstream messages, broaden credentials, relax trust, release or deploy.
