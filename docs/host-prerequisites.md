# Host prerequisites

The package inventory records package releases and complete lock observations. The tools below also depend on operating-system components, device capabilities or separately distributed resources. Each row applies only to the named platform or feature. Record the actual versions and the outcome of the relevant smoke test in that environment.

| Capability | Required components | Verification |
| --- | --- | --- |
| Source checkout and TLS certificate tooling | Git and an OpenSSL CLI. Git for Windows can supply OpenSSL. | Run `git --version` and `openssl version` in the same execution environment as the certificate tooling. Verify its TLS regression before recording success. |
| Windows desktop | MSVC C++ Build Tools, a compatible Windows SDK, and Microsoft Edge WebView2 Runtime. | Build the locked native shell and exercise its launch, IPC and shutdown regression on Windows. |
| Linux desktop | A C/C++ toolchain, WebKitGTK 4.1 development files, OpenSSL development headers, the Ayatana app-indicator development package, librsvg development files, and patchelf. | Verify native headers/linking through a locked build and run the applicable desktop test. |
| macOS desktop | Xcode and its command-line tools. | Check the selected developer directory and build and run the shell on macOS. |
| Android | The Android SDK platform-tools, SDK licenses accepted by the machine owner, a matching JDK, the selected Android API/build-tools/NDK and Rust target support. | Check SDK inventory, Rust targets and the JDK, then build for the chosen ABI. Versioned SDK components are in the package inventory. |
| iOS | A macOS host, the chosen Xcode release, CocoaPods, simulator or device SDK and matching Rust targets. | Inspect SDK and target availability, build for the target, and run a simulator/device smoke test when required. |
| OCR and document extraction | Native Xberg OCR needs Tesseract language resources for English and Czech. Optional Python extractors each require their own compatible environment and model assets. Marker on Windows requires the specifically tested Surya/Marker versions and an owned llama.cpp helper for the balanced profile. OpenDataLoader uses the declared Java runtime. | Probe each backend independently and extract a small document covering its configured OCR, image or structure path. Distinguish machine-specific installed wheel observations from reproducible input locks. |
| Audio conversion and local synthesis | FFmpeg and ffprobe binaries. Optional whisper.cpp, Piper, Chatterbox and OmniVoice integrations require their configured engine and matching local models. Select compatible device builds of the Python and accelerator libraries. | Probe both binaries, validate the configured input files and run a feature-specific offline synthesis or transcription fixture. A complete model directory and reference transcript are required for the reviewed OmniVoice reference-speech path. |
