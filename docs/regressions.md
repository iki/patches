# Package regressions

The catalog gate verifies registered artifacts and provenance. Run the package regressions below separately when reproducing a defect, testing a new release, or retiring a fix. Use the actual installed package and platform, and record the versions, package graph, patch digest, fixture revision, command and outcome. [Catalog gate](../VERIFICATION.md) · [Environment setup](../environments/README.md) · [Host prerequisites](host-prerequisites.md)

## Running the standalone fixtures

1. Provision the selected JavaScript member with its exact Aube lock, platform binaries and the designated runtime. The current web profile uses Bun 1.4.5. Select Bun 1.4.2 explicitly for the historical mobile controls. For the historical Wrangler or Portless fixed case, bind the matching canonical bundle in a separate patched installation. Preserve the unpatched baseline for comparison.
2. In that member, create a fresh physical `regression-fixtures/` directory. Copy the fixtures and companion files named below from the reviewed catalog revision, preserving their relative paths under `packages/`. Compare each source and destination with the Git blob at `<revision>:<relative-path>` using `git hash-object --no-filters`. Use the fixture copy only after all three IDs agree. This puts both script-relative ESM imports and the fixtures’ working-directory-based package resolution inside the intended member.
3. Set the working directory to the member containing its installed `node_modules`. Run each staged `.test.mjs` separately with the pinned Bun, for example `bun test --timeout 120000 ./regression-fixtures/packages/workers-sdk/adapters/wrangler-local.test.mjs`. Select a case deadline that covers its native children and preserve the timeouts in the fixtures. Run the Portless standalone script with its package directory as shown below. The per-process invocation keeps global fetch and module changes isolated.
